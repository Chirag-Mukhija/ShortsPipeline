# Plan: the edit + graphics stage (stage 6) and the rough cut gate (stage 7)

Written 2026-11-16. Not built yet. The creator approved the recommendations (2026-11-16): two runner commands allowed, no burned-in captions, no separate edit-plan gate. Their four additions are folded in below.

## What we learned that shapes this
- **The one-shot worked.** Opus, given the plan, sketch, script cues and word timings, made Beats 1–2 of video 001 at a level the creator scored top on everything (`packages/video/src/oneshot/Beats12.tsx`). It worked because of three things: full context, visuals tied to `narration.json` word times, and the designer **looking at its own stills and fixing them**. The stage repeats exactly that, per beat.
- **The parked attempt failed** on a scratch AI voice, bespoke throwaway code, and footage nobody was asked for. All three are now solved or planned for: real narration exists, the library exists, and footage gets an explicit request list.
- **The library exists:** 34 themes and ~530 animations, with a catalog the agents can read (`data/library/catalog.json`) and a preview still for every entry. Scenes are built by composing library pieces and adding new ones only where nothing fits.

## The flow inside the stage
```
record done (or cue sheet approved on music-only)
  6a  edit plan        showrunner → edit/plan.md + edit/edit.json + "What I need from you" footage list
  6b  beat graphics    motion designer (Opus), one beat at a time → edit/scenes/beat-NN.tsx, checked by its own stills
  6c  assemble         code (no agent) → each beat rendered as its own clip, joined, narration + ducked music mixed
  7   rough cut GATE   website: watch, pin notes to timestamps → only the beats with notes are redone and re-rendered
  7b  promote          the creator ticks new pieces worth keeping → generalised into the library
```

### 6a. Edit plan (showrunner, cheap)
- **Read:** script beats and `[ON SCREEN]` cues, the word timings, the plan's look and any **Look** pick, sketches and "part of the idea" attachments, and the library catalog.
- **Pick the look:**
  - If a library theme matches the plan's look, use it.
  - If not, the video starts a **new theme folder**, and its new pieces are promotion candidates afterwards.
  - A video can mix a main theme with a core transition, but never borrow pieces across themes.
- **Write `edit/edit.json`:**
  - one entry per beat: start/end from word timings, theme, scene file, the library pieces it should use, and new pieces needed
  - the music bed
  - the footage slots
- **Write "What I need from you"** (shown on the website as a checklist):
  - every screen recording or photo the beats want, with length and content
  - upload buttons that put files into `media/`
  - any slot still empty renders as a clean labelled placeholder, never a broken frame

### 6a+. Look test (when the theme isn't certain)
- If neither the plan nor your Look pick settles the theme, the showrunner picks 2–3 candidate themes and renders **one or two style frames per theme using this video's own hook and key line**: real words, not demo text.
- The frames are built from the theme's catalog pieces, so this is cheap: no designer run, just props and a still render.
- You pick on the website. In autonomous mode the showrunner picks and logs why.

### 6a++. Footage is never used raw
Every screen recording, photo or clip goes through a **treatment from the chosen theme** before it appears. Each theme exposes a `FootageFrame`; themes that lack one get it built the first time a video needs it. Treatments include:
- **Framing:** device or window frame, rounded corners, shadow and backdrop.
- **Crop:** to the region that matters.
- **Camera:**
  - auto-zoom on clicks and cursor rests
  - slow push-ins
  - speed ramps through boring parts
  - freeze-frames with callouts
- **Highlighting:**
  - spotlight dimming
  - magnified typed input
  - blur boxes for anything private
- **Colour to match the theme:**
  - duotone, halftone or riso grain for print themes
  - glyph rendering for ASCII
  - scanlines for retro
  - a light grade and sharpening for clean UI themes

Honest limit: local tools can't invent detail a recording doesn't have. Record at the highest resolution you can, at 1080p or above, and hide the desktop clutter. The treatment does the rest.

### 6b. Beat graphics (motion designer, Opus)
- **One scene file per beat:** `videos/NNN/edit/scenes/beat-NN.tsx`, importing `@library/core` and `@library/themes/<theme>`.
- **A context pack per beat,** generated by a script so the agent doesn't spend tokens gathering it:
  - beat text and its word times
  - cues
  - the sketch for that beat
  - the theme's catalog entries (`api`, `useFor`, preview paths)
  - the benchmark rules
- **The quality loop:**
  - render stills at each cue word and at the beat's mid-points with `scripts/render-stills.mjs`
  - look at them and fix clipping, crowding, timing and readability
  - repeat, capped at 3 rounds
- **Beat-wise, never one-shot for the whole video:** each run builds one beat (two short beats at most) with a fresh context, so quality doesn't fall off toward the end. Runs one at a time, or two in parallel at most, for the laptop's sake.

### 6c. Assemble (code only)
- **`LongVideo` composition:** narration audio, beat scenes in sequences at their word-time ranges, core transitions, footage slots, and the music bed.
- **Per-beat clip rendering:** each beat renders to `renders/beats/beat-NN.mp4`, cached by a hash of its scene file and inputs. Clips are joined with ffmpeg and the audio is mixed once. Changing one beat re-renders only that beat, which saves time and heat.
- **Previews render at half size** for the rough cut; the final render is 1080p. Renders use the GPU (`remotion.config.ts`) with capped concurrency.
- **Music:**
  - the track from the Look/Music pick or the team's choice
  - ducked automatically under speech, using the word timings (about −18 dB while talking, back up in gaps, gentle fades)
  - the license credit line written to `edit/credits.md` for the description later
- **Music-only:** the cue sheet's beats are placed on the track's BPM grid (core `Track`, `useSong`) instead of word times.

### 7. Rough cut gate (website)
- **A Rough cut page:**
  - the player
  - a beat timeline under it
  - **click to pin a note at the current time**, saved to `edit/notes.json`
- **Approve or send notes.** Notes go to the next run, which only touches the beats they fall in, then re-renders just those clips.
- After approval, the stage is done. Package and private upload come next, in a later build.

### 7b. Promote to the library
After approval, the creator ticks which new pieces were good. A short agent run then:
- moves each piece into its theme
- turns its text and times into props
- adds a catalog entry
- renders previews

The library grows by what real videos needed.

## Keeping videos from looking stale
- **Usage log:** the library records which pieces each video used (`data/library/usage.json`, shown on the Library page).
- **Signature moments** (a theme's hero animations) aren't reused within the next 3 videos in the same theme. Workhorse pieces (lower thirds, lists, source labels) can repeat freely; that consistency is a brand, not staleness.
- **Fresh share per video:** at least about a third of each video's scenes are newly designed, and the good ones are promoted, so the library keeps growing.
- **Variation inside a theme:** accent colour, layout grid and camera grammar can shift per video while the theme stays recognisable.

## The Edit page (what you'll be able to do)
- **Watch:**
  - the assembled preview with a player
  - a timeline underneath with tracks for your narration (waveform and words), the beats (scene blocks with thumbnails), footage, and music (with its ducking curve)
- **Per beat:**
  - its cue stills and status (planned, building, ready, approved)
  - **Regenerate this beat** with a note, keeping each version as a **take**, like on the Record page: switch between v1, v2 and v3, and lock the one you like
- **Fix without regenerating:**
  - edit on-screen text
  - **nudge a cue** earlier or later against its word, or make a hold longer or shorter
  - pick the transition between two beats from the theme's set

  Only that beat re-renders.
- **Footage:**
  - the "What I need from you" checklist and uploads
  - for each clip: set in and out points, drag a crop box, mark areas to blur, set speed, preview the treatment
- **Music:**
  - choose a track (or let the team choose), set its volume, duck depth, start point and fades, or mute it
  - the credit line is kept automatically
- **Rough cut:** pin notes at the current time, then approve, or send the notes back. Only the beats with notes are redone.
- **Render:** a quick half-size preview of the whole video, re-render one beat, or a final 1080p render, all with progress shown. The export gives you the mp4 plus the caption file.
- **Not here:** narration edits stay on the Record page. Re-exporting there flows into the edit automatically, because everything is pinned to word timings.

## Direction layer (added 2026-11-16, from the creator's reference repos and reels)
- **Why:** the creator felt the themes "look like websites, not videos".
- **Research:** two MIT motion-video skills (bang-motion, huashu-art-motion) and four reels, distilled in `data/references/direction/`.
- **The rulebook,** `packages/video/src/library/DIRECTION.md`, sits above every theme. Themes are skins; direction is the cinematography: one world with a camera, shot sizes, motivated transitions with depth, living layered surfaces, text rules, rhythm.
- **New core building blocks** (official Remotion motion-blur, noise, shapes and paths, allowed in core only):
  - camera rig: shot sizes, `frameOn`, parallax depth, HUD, motion blur, depth of field
  - surfaces and life layers
  - transition pack: maskGrow, whip, card3d, lightSweep, pushThrough, overlap, matchCut, colourFlash
  - text pack: 8 doors, Emphasis, Slam, CountUp, Caption
  - cue helpers: cueWord, revealStart, beat pulse, impact

  27 demos in the core catalog.
- **Storyboard (the creator's middle ground instead of reading shot tables):**
  - the edit plan writes a shot list per beat (subject, action, shot size, camera move, ≤ 8 words, transition out)
  - `assemble.mjs --animatic` renders it as labelled boxes and a moving camera over the narration, cached per beat
  - the Edit page has a Cut / Storyboard switch and a Shots panel to edit any shot (one beat re-renders in about 30 s)
  - **Approve storyboard** gates the designers
- **QA:** red flags block a beat (creator's choice); yellow flags are reported. The automatic still checks aren't scripted yet, so for now the designer checks them by eye.

## Build order (each step ends in something you can watch)
1. ✅ **Engine (done 2026-11-16).**
   - Scenes live in `videos/NNN/edit/scenes/beat-NN.tsx` and import `@library/...` (alias in `packages/video/remotion.config.ts`).
   - `edit/edit.json` lists the beats (`start`/`end` in video seconds), the narration and the music.
   - `node scripts/assemble.mjs <videoId> [--final] [--beats beat-02]`:
     - generates the entry and a per-video `tsconfig.json`
     - renders each beat as a cached clip
     - joins them and mixes narration with a music bed that ducks under the voice via a sidechain compressor, measured at about 14 dB down while speaking and back to full in pauses
   - **Measured on video 001 Beats 1–2 (1:54, half size, GPU):**
     - first assembly about 60 s (~50 frames/s per beat)
     - one beat changed: 39 s
     - nothing changed: 4 s
   - Frames are identical to the one-shot benchmark.

   - **Test:** move the existing Beats 1–2 one-shot into `videos/001/edit/scenes/`, assemble, and get the same video plus a music bed.

## Cost
- **Steps 1, 2, 4, 5:** normal coding sessions on Opus in the main session. About one usage window each, steps 4–5 a little more.
- **Each video's graphics:** roughly 4–5 Opus designer runs for an 8-beat video at two beats a run. Each is about the size of one library theme build (150–250k tokens), so **about one 5-hour window per video**, plus small runs for rough-cut notes.
  - It gets cheaper as the library covers more of what videos need.
  - Sonnet could be tried for revision runs only.
- **Rendering is local and free.** Half-size previews of an 8-minute video should take minutes, not hours, with the per-beat cache. To be measured in step 1.

## Decisions for the creator (answered 2026-11-16: recommendations approved)
1. **Runner permissions.** The headless runner may only run a fixed list of commands, and that list currently has no render command. The stage needs two narrow additions:
   - `node scripts/render-stills.mjs` (designer self-checks)
   - `node scripts/assemble.mjs` (beat clips + join)
   - **Recommend: allow exactly these two.**
2. **Captions.**
   - **Recommend:** none burned in; upload `narration.srt` to YouTube at the package stage.
   - Key words already land as on-screen text through the themes.
3. **An edit-plan gate before graphics?**
   - **Recommend: no separate gate.** The footage checklist is the only thing that waits on you, and the rough cut is the real gate. In gated mode, a single "here's the plan and the theme" question can be on if you want it.
4. **Music for video 001:** pick a candidate on the Library page, or let the team choose.
5. **Your face on camera:** not in this build. A "camera during the take" option stays on the later list.
